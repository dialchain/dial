# Distributed Immutable Assertions Log (DIAL)
## Abstract
The DialChain is a distributed log with the main purpose of turning each inserted __declaration__ into an __immutable assertion__. The DialChain can be seen as a log holding __state of tokens__. Tokens can be used to represent digital assets, people, organizations or even real estates, in short everything addressable.

A __time window__ is the lapse of time in which there is a deterministic partitioning of tokens and validators into __neighborhoods__. Partitioning is achieved by calculating the distance of each validator (resp. Token) to the __time window anchor__.

This __Ephemeral Neighborhood Protocol (ENP)__ secures the unpredictable but deterministic assocciation between validators and tokens in any given time window, hereby preventing validators from extracting additional value from their priviledged role of validator. In the picture above,

- Black dots are eligible validators. These are validators registered for performance during time window (tw). Registration takes place in time window tw-2.
- Blue dots are tokens. Each declaration creating or modifying a token is automatically assigned to a neighborhood (partition) by computing the distance of the token-id to the time window anchor.

## Core Principles
__Instant Finality__ is provided as the __Ephemeral Neighborhood Protocol (ENP)__ defines a small enougth set of validators to take care of each token during the open time window. Double spending can only occur with the complicity of all validators of the host neighborhood. One good validator is sufficient to prevent double spending. A participant receiving a positive result from all validators of a neighborhood can assume finality.

__Organic Scalability__ is provided. As (1) the DialChain is designed to allow each participant (e.g mobile phone) to perform the duty of a validator, (2) growing number of end user will lead to a growing number of validators, (3) growing number of validators will lead to a growinng number of neighborhoods.

__Unlimited Blocksize__ is provided as all declarations submited for publication during a given time window are validated and included into the time window protocol.

__DETerministic Ordering of EXecution (DETOX)__ is essential for the adoption of blockchain by other industries. As no transaction recording/execution system will work at scale, if it cannot provide a guarantee for the time and order of execution of submitted transactions.

__Spam Resistance__ is provided despite the open and permissionless character of the DialChain. Participants are registered with the system using a __Time Degarding Proof of Work Protocol__. According to this protocol, (1) all requests sent to the Dial network are associated with a payment. (2) Curency needed to perform payment (service currency) is self generated by each participant and constrained in it usage. (3) Initial generation of service currency is associated with difficult proof of work. (4) As participant built reputation, less difficulty is required for the proof of work needed to generate service currency. Currency earned by network service providers is subsequently free of usage accross the network.

__DialChain File Size__ is kept low as only active tokens are included into the validation process. A token is active if (1) the token has a controller and (2) is not expired. Whole preparing for the performance of a time window, a Dial validator only needs to collect and index active token associated with the target neighborhood. Therefore the more neighborhood we have, the less file are downloaded by each validator.

__Sustainability__ is provided as reserves needed to maintain a token during their given lifetime are collected from the issuing participant with the publication of corresponding declarations. The collected revenue is held in the DIAL treasury and distributed to validators for each hour of relevance of the concerned token.

## Monetary Policy
The DialCoin is the utility currency used in the Dial network. The dial coin emmission process follow two steps: 

(1) Participants to the dial network perform proof of work to generate time and space limited __Dial Service Coins__ that can only be used to pay for services on the Dial network for the given time period. They expire when not consumed in the given time period.
(2) By earning __Dial Service Coins__, Dial network service provider tranform them into __Dial Coins__. These coins are then put into the free market by those service providers.

As the generation of Dial coins is bound to participant effectively consuming Dial network services, there is no need to put a cap on the number of Dial coins that can be produced. There is also no intent on inflating the valuue of the Dial by producing scarecity, as the main purpose of the Dail is to empower the service economy in the Dial network.
